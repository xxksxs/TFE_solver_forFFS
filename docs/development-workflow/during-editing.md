# 编辑中约束

修改期间应尽量保持变更小、职责清晰、可回归。

## 代码边界

- 修改应限制在职责归属清晰的模块内。
- 修改接口时，先更新公共头文件，再更新实现。
- 除非任务明确要求，否则不要改变现有 CLI 行为。
- 保持 `src/main.cpp` 为轻量入口。
- 保持 MKL 直接求解和非 MKL fallback 两条路径都可构建。

## 数值代码约束

- 不要孤立修改端口模式、端口装配或 S 参数投影中的单个环节。
- 不要把边自由度当作节点标量处理。
- 不要在 FEM 装配中硬编码本应来自材料或输入文件的参数。
- 不要用高残差结果解释物理现象。

## 文档约束

- 文档路径必须与实际文件一致。
- 新增专题文档时同步更新所在目录的 `README.md`。
- 顶层兼容入口应指向新的详细文档。
