# 可复现的运行记录与归档

`Application.cpp` 在输出根目录内创建同卷暂存目录。成功写完必需结果、检查文件并关闭流后，才发布到委托的 `result_<算法>` 子目录。同名重跑使用唯一后缀。成功目录的权威标志为 `run.json` 的 `status=ok`。求解、输出或发布失败返回非零，在可写时保留日志和失败报告。WCAWE 的 `basis_condition.csv` 写入及关闭错误会传播到主流程。

schema 2 保留小数选项的双精度精度，记录 AEDT、网格、构建时源码集合与可执行文件的 SHA-256，并记录 Git 修订、源码工作树状态、编译信息、实际线性求解后端及线程信息。MKL 和 PARDISO 字段记录运行库当前线程上限，OpenMP 字段记录所传环境变量。对不同平台和后端的线程上限，按各自字段的含义解读。

`run.json` 保存 MGAWE 真实残差自适应开关和容差及 WCAWE 残差诊断开关。`diagnostics.json` 的 `true_residual_acceptance` 区分 `met`、`unmet`、`diagnostic_only` 与 `not_evaluated`。真实残差的达标口径由诊断文件的容差、未达标频点和各样本共同给出。

比较脚本先验证实验输入和实际频点，再生成独立的比较目录。归档依照算例文件夹结构核对项目与运行输入的指纹，并保存输出文件校验清单。历史兼容、命令及构建依赖见[工程参考](../engineering-reference.md)。

比较报告中的 `aedt_sha256` 和 `mesh_sha256` 标识求解输入。归档清单 `SHA256SUMS.txt` 记录每份输出的字节哈希。归档前检查诊断中的算法和成功状态，以及 S11、S21 复数列、有限数值与严格递增的正频点。带有 `run.json.pending` 的目录仍处于发布阶段，比较脚本会拒绝读取，包括显式启用历史兼容时。

归档暂存目录继承算例 `results/` 的默认访问权限，校验完成后在同一卷发布。WCAWE 归档还要求 `basis_condition.csv` 存在且非空。

回归使用小波导算例、三频点、零阶棱元、单模端口和单线程 PARDISO。覆盖首次运行、同名重跑、两个进程并发、迭代求解失败、CSV 和 WCAWE 基条件输出故障、比较输入拒绝、显式历史兼容及归档哈希复核。缺少 SHA-256 的历史记录按明确标注的兼容口径复核。

## 2026-11-21 IOStructure 归档复验

用当前 Windows Release 版本与正式算例的 AEDT、NGMesh 复算真实残差自适应 MGAWE。运行记录包含自适应开关、`1e-3` 容差和两个输入的 SHA-256。101 点残差均达标，复数 S11、S21 与此前的临时输出逐值一致。脚本核对全部输出后发布，并拒绝同名归档、缺少复数 S 参数的 CSV、错误算法诊断、非正频点及非有限值。通用 HFSS 比较同时复验了独立重跑发布、输入指纹及显式历史兼容。
